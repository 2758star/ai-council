# Personal Secretary App 闭环增强手测脚本（v0.2.2）

适用范围：
- 通知中心闭环
- Web Capture & Watch 变化闭环
- AI 草稿应用闭环

目标：
- 验证“动作后可追踪、可回执、可定位”是否成立
- 验证幂等行为（重复点击不误操作、不静默）

## 一、通知中心 → 任务闭环

前置：
1. 打开设置页：`设置与集成 -> 通知中心 -> 通知列表`
2. 准备至少 1 条未读通知（建议有 `relatedType` 或包含 URL）

步骤：
1. 点击通知卡上的“转为任务”。
2. 观察：
   - 出现成功 toast；
   - 通知卡状态更新（已读/关联对象）；
   - 顶部“回执历史”新增一条 `通知中心 / 已转任务`。
3. 再次点击同一条“转为任务”。
4. 观察：
   - 不会重复创建任务；
   - 回执显示幂等提示（已有关联任务）。
5. 点击“打开关联对象”。
6. 观察：
   - 跳转到对应模块（任务/项目/监控/简报/资料库）；
   - 回执历史新增 `通知中心 / 成功`。

通过标准：
- 操作后必须出现“toast + 回执历史 + 卡片状态变化”三联反馈；
- 重复点击不产生重复任务，不静默失败。
- 关闭并重新打开应用后，回执历史仍可在设置页看到（验证本地持久化）。
- 若从 Dashboard 的“最近动作”点击“打开关联对象（任务）”，应跳转任务页并自动定位目标任务。

## 二、网页变化 → 任务闭环

前置：
1. 打开设置页：`设置与集成 -> Web Capture & Watch -> 变化`
2. 至少存在 1 条待处理变化

步骤：
1. 对某条变化点击“转任务”。
2. 观察：
   - 变化被标记为已处理；
   - 回执历史新增 `网页监控 / 已转任务`；
   - 文案包含任务编号。
3. 对另一条变化点击“稍后处理”。
4. 观察：
   - 该条变化从当前待处理视图隐藏；
   - 卡片显示“稍后处理至”时间；
   - 回执历史新增 `网页监控 / 已稍后提醒`。
5. 使用“批量转任务”。
6. 观察：
   - 回执历史显示成功数 / 跳过数 / 失败数；
   - 失败时给出失败示例，不静默。

通过标准：
- 单条与批量都必须生成可读汇总回执；
- 已稍后处理项不会在待处理列表刷屏；
- 同一变化重复“转任务”会触发幂等提示。

## 三、AI 草稿 → 应用闭环

前置：
1. 打开 AI 页：`AI 助手 -> 草稿队列`
2. 至少有 1 条草稿

步骤：
1. 点击“查看差异并应用”。
2. 观察：
   - 打开确认侧栏；
   - 显示新增条目、潜在重复、高优先级、已排期条目、预计总时长。
3. 点击“确认应用”。
4. 观察：
   - 成功 toast；
   - “最近应用回执”显示草稿 ID、新增数量、影响任务数量；
   - 点击“查看影响对象”可跳转到任务页。
5. 对同一草稿再次应用。
6. 观察：
   - 系统给出已应用回执，不重复创建。

通过标准：
- 应用前必须有差异确认；
- 应用后必须有标准回执与定位入口；
- 重复应用不重复写入。
- 应用失败时也要写入回执历史，并区分 `provider_not_ready / target_missing / write_failed`。

## 三点五、通知建议池闭环

步骤：
1. 在 `设置与集成 -> 建议池` 对某条建议点击“**一键转任务**”。
2. 观察：
   - 成功 toast；
   - 回执历史新增 `通知中心 / 已转任务`；
   - 建议列表状态同步刷新。
3. 对已忽略建议重复点击“**忽略**”。
4. 观察：
   - 回执显示“已忽略（幂等保护）”；
   - 无重复写入。
5. 在 `通知中心 -> 筛选与批量` 点击“**生成建议草案**”。
6. 观察：
   - 回执历史新增 `通知中心 / 成功`（或失败回执）；
   - 建议池与通知统计刷新。

## 四、回归与编译

步骤：
1. 执行 `npm run build`
2. 打开桌面应用，快速走一遍上述三条链路

通过标准：
- 构建通过；
- 页面无明显卡死、无空白；
- 闭环动作在页面层可见可追踪。
