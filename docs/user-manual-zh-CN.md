## 1. 这是什么系统

Personal Secretary App 是一个本地优先（Local-First）的桌面秘书系统，核心目标是让你用一个软件完成：

- 申请项目管理（学校、项目、材料、文书版本、建议池）
- 任务与日程执行（Today/周/月/年/日历/看板）
- 资料库管理（本地文件扫描、标签、收藏、关联项目与任务、预览）
- 番茄钟专注统计
- 错题、习惯、日记与灵感沉淀
- AI 摘要与日志
- 飞书提醒、Webhook 入站、官网监控、通知中心

你可以把它理解为：一个面向“长期个人项目管理”的本地桌面秘书底座。申请只是第一阶段场景，后续也可以切换到求职、考试、创作等场景。

---

## 2. 核心设计原则

1. 本地优先：核心数据在本机 SQLite，不依赖云端才能用。  
2. 可扩展：飞书、监控、云端 relay 都是增强层，不是必需层。  
3. 结构化：任务、通知、日志、简报都有可追踪状态。  
4. 可持续：强调长期使用，不是一次性填表工具。

---

## 3. 技术栈概览（给你做维护时参考）

- 桌面壳：Tauri 2
- 前端：React + TypeScript + Vite + Tailwind
- 状态：Zustand
- 数据：SQLite（本地）
- 后端逻辑：Rust（`src-tauri`）
- 云端可选：Cloud Run Relay（`cloud/relay`）

## 4. 安装与启动

## 4.1 先决条件

1. Node.js 20+
2. Rust 工具链（`cargo` 必须可用）
3. macOS 下 Tauri 依赖环境

## 4.2 安装依赖

```bash
cd /Users/hujunbo/Documents/Playground
npm install
```

## 4.3 开发运行（桌面版）

```bash
npm run tauri:dev
```

## 4.4 打包安装包

```bash
npm run tauri:build
```

## 4.5 常见启动报错

### 报错：`cargo metadata ... No such file or directory`

说明 Rust 未安装或 PATH 未生效。  
处理：安装 Rust，重开终端，再执行 `npm run tauri:dev`。

### 报错：飞书入站无响应

先检查本地 Webhook 服务是否已启动（设置页可启动/停止），再检查飞书事件订阅地址是否配置正确。

## 5. 首次使用建议（10 分钟）

1. 进入“设置 → 资料目录”，配置本地资料路径。  
2. 在“资料库”执行一次“扫描索引”。  
3. 进入“申请管理”创建你的学校项目。  
4. 进入“任务日程”创建本周关键任务与日程。  
5. 在“设置 → 飞书联动”填好 Webhook，发送测试消息。  
6. 在“设置 → 秘书简报”设置晨间/晚间时间（默认 `08:00 / 22:30`）。

## 6. 页面与功能说明

## 6.1 总览（Dashboard）

用途：每日指挥台。  
你可以在这里快速看到：

- 今日任务、进行中申请、紧急 DDL、AI 活动
- 冲刺风险与最近通知
- 晨间简报、晚间回顾入口
- 结构化快照（历史未完成、今日应完成）

推荐习惯：每天先看这里，再进入任务页执行。

## 6.2 申请管理（Applications）

用途：项目推进中心。  
核心能力：

- 项目 CRUD（学校、项目、DDL、状态、优先级）
- 材料项 CRUD（文书/推荐信/成绩/作品集等）
- 文档版本管理
- 官网建议转任务
- 示例数据填充

推荐习惯：每个项目都维护“状态 + 缺失材料 + 下一个动作”。

## 6.3 任务日程（Tasks）

用途：执行中心。  
已实现能力：

- 执行区：Inbox / 日 / 周 / 月 / 年 / 看板
- 日历区：任务与日程同屏显示
- 规划区：AI 紧急分级、周拆解、Carryover 补偿池
- 分层：任务/日程可筛选
- 冲突检测：时间冲突、负荷过高、高优先过多
- 延期记录：原因代码 + 备注
- 周期任务：日/周/月/自定义间隔
- 完成复盘标签：顺利完成 / 被打断 / 超时完成 / 提前完成
- DDL 倒计时
- 自动重排（按规则）：固定课/额外课/看剧夜/补偿夜

新增融合能力（本版重点）：

- 执行快照条：历史未完成 + 今日应完成 + 规则检查
- 日历格子显示“遗留 N”
- 看板执行激励：完成率、连续天数、优先提醒
- 一键生成“双线模板（任务+日程）”

## 6.4 资料库（Library）

用途：本地资料中枢。  
核心能力：

- 扫描并索引配置目录文件
- 搜索、按分类过滤、收藏
- 批量标签
- 批量关联项目/任务
- 多类型预览（文本内联、其他类型降级说明）
- 直接系统方式打开文件

建议目录按用途分层：IELTS / GRE / 申请文书 / 推荐信 / 作品集。

## 6.5 专注（Focus）

用途：番茄钟执行与统计。  
能力：

- 绑定任务开始番茄钟
- 暂停/提前完成/放弃重置
- 今日与本周专注时长统计
- 中断次数记录

## 6.6 错题（Mistakes）

用途：错因追踪 + 复习提醒。  
能力：

- 快速记录考试类型、题型、错因、纠正方法
- 设置复习日期并显示风险状态（正常/预警/已过期）
- 按考试类型筛选

## 6.7 习惯（Habits）

用途：习惯创建与打卡。  
能力：

- 习惯 CRUD
- 今日打卡
- 最近日志回看

## 6.8 日记与灵感（Journal）

用途：长期沉淀。  
能力：

- 日记记录（类型、标题、内容）
- 灵感记录（标签）
- 最近记录快速回看

## 6.9 AI 助手（AI）

用途：摘要与模型配置。  
能力：

- Provider 切换（本地规则 / Gemini）
- 保存 API Key 与模型名
- 生成智能摘要
- token、耗时、成本日志查看

## 6.10 设置与集成（Settings）

用途：系统配置总入口。  
分区：

- 资料目录
- 飞书联动
- 官网监控
- 建议池
- 通知中心

飞书页已包含：

- Webhook 推送配置
- 本地 Webhook 入站服务控制
- JSON webhook 测试入口
- 命令模板
- 晨间/晚间简报定时配置
- 飞书入站日志

## 6.11 数学错题本（Math Notebook）

用途：一键启动外部 `GRE_Error_Log` 工具。  
你无需手动 `cd` 执行命令，页面按钮可直接启动并打开。

## 7. 任务日程模块的推荐工作流（按天）

## 7.1 早上（08:00）

1. 在总览生成或查看晨间简报。  
2. 看“历史未完成 + 今日应完成”。  
3. 进入任务页点击“按规则自动重排当天”。  
4. 确认今天的 3 个关键动作。

## 7.2 白天执行

1. 按 Today 卡片推进。  
2. 短任务直接打勾。  
3. 延期必须记录原因。  
4. 中断后用番茄钟重启任务。

## 7.3 晚上（22:30）

1. 生成晚间回顾。  
2. 检查延期原因统计。  
3. 把必须顺延项送入 Carryover 池。  
4. 预排次日第一件事。

## 8. 飞书联动说明（非常重要）

## 8.1 你可以只用单向推送

适合“轻量提醒”：

- App 推送通知到飞书
- 你不从飞书反向控制 App

优点：最稳定，配置最少。

## 8.2 你可以开双向（飞书发消息控制系统）

需要：

1. 飞书事件订阅回调地址可访问。  
2. 本地监听持续运行，或使用云端 relay 持续运行。  
3. 机器人权限、事件订阅、发布版本都正确。  

如果电脑会关机，建议上云（Cloud Run relay），详见：  
[cloud-deploy-quickstart.md](/Users/hujunbo/Documents/Playground/docs/cloud-deploy-quickstart.md)

## 9. 数据与备份建议

## 9.1 数据位置

- 核心结构化数据：SQLite（由 Tauri 管理）
- 文件资料：你配置的本地目录

App 左下角会显示数据库路径，可用于定位备份文件。

## 9.2 备份策略（个人版推荐）

1. 每周备份一次 SQLite 文件。  
2. 同步备份资料目录（尤其文书、推荐信、作品集）。  
3. 大改前做一次手动快照（数据库 + 资料目录一起备份）。

## 10. 常见问题 FAQ

### Q1：为什么点飞书没回执？

先看设置页“飞书链路日志”，确认消息是否入站。  
如果没入站，通常是回调地址或事件订阅问题。  
如果要 24h 在线监听，需云端部署 relay。

### Q2：任务和日程有什么区别？

当前系统是“同库管理，执行分层展示”：

- 日程偏时间块与课程安排
- 任务偏可交付事项

它们在日历会一起显示，执行区可切换筛选。

### Q3：为什么我改了规则但计划没变？

规则需要先点“保存规则”，再点“按规则自动重排当天”才会应用。

### Q4：我只想快速用，不想折腾配置？

最短路径：

1. 建项目  
2. 加任务  
3. 扫资料  
4. 每天看晨报  
5. 晚上回顾
